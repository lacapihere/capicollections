01 — Context

The Project

IPRAF is a structured analytical system for professional license reaccreditation and renewal. Its content, methodology, classification, and editorial logic already exist and belong to the client — this is not a traditional course or a conventional question bank.

Our role as the technology provider is to turn that existing structure into a functional, proprietary, and scalable web platform. We will not create, reproduce, or redefine the client's methodology or intellectual content.

The database currently holds approximately 388 core analytical records, organized by subjects and subcategories, plus related information that must be preserved during migration. The client will provide an Excel file for development.

03 — Technical Architecture

How It's Built

Frontend

Next.js (App Router) + TypeScript + Tailwind. Server-rendered by default: content never travels to the client as open JSON, which protects the client's asset and gives the best mobile reading experience.

Backend

Supabase — Postgres, Auth, and Storage. Access logic lives in RLS, not in the frontend.

Hosting

Vercel. Custom domain, automatic SSL, branch previews for Draft validation.

Search

Native Postgres: tsvector + GIN, pg_trgm, unaccent. No external service — at 388 records it isn't justified, and it avoids one more recurring cost.

Authentication

Supabase Auth, email + magic link and password. Server-side session.

Payments

Stripe Checkout + signed webhook that writes to entitlements. Access is granted by the database, never by the browser.

Import

Node script with exceljs → staging → validation report → idempotent upsert. Runnable as many times as needed.

Admin

Custom panel within the same app, with an editor role, audit_log history, and xlsx/csv export.
